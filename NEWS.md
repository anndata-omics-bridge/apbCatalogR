# apbCatalogR 0.99.0

* First version: apb-catalog's API in R on the apb-catalog bundle: the R6 classes `Catalog`, `DataCatalog` and `Reference`, `catalogues()`, `rule_coverage()`, `catalogue_table()` and the conditions `UnresolvedField` and `MissingRequiredField`.
* `read_parsed_levels()` reads an APB Parquet result into `ParsedLevels`, one anndataR `AnnData` per level. It also reads apb2's `.h5ad` and `.duckdb` results into the same `ParsedLevels`; Parquet needs the suggested `arrow` package and DuckDB the suggested `duckdb` and `DBI` packages; `.h5ad` needs only anndataR 1.2.2 or later, the first to read the text columns apb2 writes.
* Lookups ask by key: each set lists its keys in the bundle's `keys.csv`, each a kind with the qualifier values it fixes. `keys()` replaces `kinds()`, and `layer()`, `var()` and `obs()` take a key, such as `"normalized_intensity"` (kind `intensity`, normalization `run_setting`); further qualifiers, such as `unit`, narrow a lookup, and one the key fixes is an error. The `abundance` set has its `normalization` qualifier again; asking `"intensity"` where the normalization is unknown is unknown. `q_value` in `var` is the q-value across the experiment (was `global_q_value`); Sage's is `"quantification_q_value"`. `catalogue_table()` and `fields()` have `key` and `kind` columns, `rule_coverage()` a `key` column.
* `update_catalog()` downloads the bundle of an apb-catalog release; `catalog_version()` reports the bundle in use.
* The bundle holds only the catalogue tables; the synthetic results and expected answers ship as a separate test bundle in `inst/extdata/test-bundle/`.
* Bundle format 2: the catalogue sets are six CSV tables (`entries`, `entry_qualifiers`, `vocabulary`, `keys`, `requirements`, `producers`) described by `datapackage.json`; a vendor catalogue reviews every rule level the bundle's `rule_levels.csv` lists, and every qualifier lists `unknown` as a value. Bundles of format 1 are passed over.
* Entries name the software version patterns they were reviewed for, not apb2's rule files, and the bundle carries no rules: `rule_levels.csv` gives the levels apb2 converts for each software version. apb2's own columns (`ProForma_*`, `apb_Decoy`, the protein-assignment columns) are each software's entries in the `apb` set. `catalogue_table()` and `fields()` name `software_version_pattern` and have no `rule` column; `rule_coverage()` has `software_version_pattern` and neither `rule` nor `inputs`.
* `DataCatalog$new(result, ...)` composes the named catalogue sets with `apb`, which is always in; a key routes to the sets that define it, and two sets naming different fields for one key on one level is an error. Its `levels` give anndataR's slots looked up as cf_xarray does: `cat$levels$protein$layers[["maxlfq"]]` reads a key, else the level's own layer of that name, else an error; `X`, `var[[...]]`, `obs[[...]]`, `obs_names`, `var_names`; `$keys()` lists keys only.
* Snapshots are not ported: `DataCatalog$snapshot()`, `$resolve()`, `attach_snapshot()`, `stored_snapshot()`, `stale_levels()` and `ResolutionSnapshot` have no R counterpart.
